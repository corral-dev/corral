# Shared session titles

## Generation channels (owner ruling, 2026-10-15)

Keep the configured gateway channel. When the gateway URL/key is absent, automatically use an installed local Agent runtime with its existing authentication and model configuration; no separate Corral API key is required for that route. This ruling supersedes the gateway-only/retired-CLI prohibitions in the historical September records below, whose title-quality and shared-state requirements remain valid.

Both channels implement the same `TitleGenerator` contract and consume the same bounded prompt. Corral owns routing, timeouts, cache and host coordination; runtime launch/resume adapters and SessKit parsers do not own this transport. Preserve accepted titles, language rules, title-only events and runtime+session cache identity. A configured gateway failure does not silently change account/channel.

Local jobs are one-shot subprocesses, never resumed user sessions or tmux hosts: send excerpts on stdin, detach a process group, strip inherited Corral session claims, terminate the whole job on timeout. Keep user authentication/configuration in place and never copy credentials or change HOME. Run outside the user's project under a private Corral-owned workspace marked `.sesskit-ignore`, retaining the fixed prompt marker as defense in depth. Use native no-session flags for Claude/Codex/Pi; OpenCode v2 uses a private standalone server and database; Cursor uses a separate data directory while retaining its normal configuration/login. Do not delete or rewrite user histories. Keep CLI capability checks in the background worker (first-paint candidate discovery only checks executable paths). Preserve Pi provider extensions, because disabling all extensions can remove the user's configured model (`--no-tools` still excludes their tools). Capability-check installed CLI flags; an incompatible or unauthenticated backend fails over to another installed runtime without opening login flows. Local jobs run serially, and a failed local backend is not retried for every queued session in the same pass.

The inspected reference is Corral's pre-gateway `titlegen.py` (before `a87ff62`): reuse its backend boundary and native ephemeral modes, not its credential copying, persistent-session calls in the project, argv prompt delivery or random account rotation. Official references: [Claude CLI](https://code.claude.com/docs/en/cli-reference), [Claude automation/auth caveat](https://code.claude.com/docs/en/headless), [Codex exec](https://developers.openai.com/codex/cli/reference/), [Pi CLI](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/cli.md), [OpenCode standalone](https://dev.opencode.ai/v2/docs/cli), [Cursor parameters](https://cursor.com/docs/cli/reference/parameters). OpenCode DB isolation was checked in upstream `packages/cli/src/database-path.ts` and `run/run.ts`; Cursor data/config separation was inspected in the installed vendor bundle and needs real-path regression because it is not a documented stable CLI flag. Claude `--bare` is unsuitable: it bypasses subscription OAuth/keychain authentication.

The daemon must close its lock descriptor when another process already holds the lock; a focused contention test exposed an existing ResourceWarning on this exit path. Missing-channel failures may retry when a compatible local backend appears, as well as when gateway configuration becomes available; model/transport failures retain cooldown. Validate actual no-key model output, timeout descendant cleanup, unchanged user history, stable successes, five-runtime source inputs and host title propagation; test fixtures must isolate all cache writes.

**Reachability is not a model failure (2026-11-14).** A machine whose overlay route changed recorded `failure_reason=transport` for every newly listed session while the configured gateway was healthy on another existing route it already trusted; native history, activity times and fallback titles stayed correct. Check the configured endpoint's real reachability before diagnosing models, quota or the generator chain. Repair by pointing the same gateway configuration at a verified route while keeping the virtual key and model; do not switch provider/model, mint a key or restore CLI generation. Shared route guidance and the consumer follow-up live in the AgentSync [LLM gateway guide](~/.config/agentsync/docs/LLM_GATEWAY_GUIDE.md).

## Confirmed product requirement

iOS and TUI must use the same session-title generation logic, generation channel and resulting title for the same host and session; iOS must not independently generate a competing title.

**Title quality (2026-09-12):** a title must identify the session's task without requiring the reader to open the conversation. Standalone insults, `Task`, `实现` and a closing `Session recap` command label do not satisfy this for a substantive work session.

**Attachment-prefix (2026-10-07):** punctuation-only strings are never task titles, including after local cleanup removes attachment paths or URLs. A path-only clipped scanner fallback must yield to the real user request and must not suppress generation for it. Reject punctuation-only native, cached and model titles across all runtimes while preserving valid cached successes; no native history rewrite or client-specific workaround is needed.

**Confirmed cause:** Codex screenshot-led requests retain the full real request in `first_user_msg`, but their 60-character `fallback_title` can contain only a partial attachment path plus `…`. `_compact_title` checked validity before stripping paths; path removal then produced `…`, which `_temporary_title` preferred over the real request, and `resolve_initial_title` displayed that fallback while rejecting it for generation — stuck with no model call. Validate the cleaned candidate before ranking or clipping; title policy belongs to Corral, not SessKit's parser. Regression covers attachment-led requests on all five active runtimes, removed-reference punctuation, invalid historical caches/model results and preservation of valid successes. Seven affected real Codex records returned readable, generation-eligible titles, the isolated real TUI renderer displayed the corrected title, and the complete CLI gate passed in 94 seconds.

**Review gaps closed (2026-09-12):** SessKit extracts the Corral handoff digest **before** the 300-character list clip (`clip_user_excerpt`); local titles skip digest headings and `User:` / `Assistant:` role labels; short real requests are no longer dropped as "emotion clauses"; insufficient retries fingerprint bounded task input (not file size); pure insults are rejected on fallback, cached-success and model-result paths; parsed-but-invalid model output records `failure_reason=invalid`, not `transport`. Confirmed-valid cached successes stay stable. Requires SessKit ≥ 0.1.3.

## Status and scope

**Host implementation delivered (2026-09-11):** shared `TitleState` + `poll_title_updates`, remote title-only list/metadata events with additive `revision`, the remote path injecting the same title daemon launcher as the TUI, and generation transport on the shared OpenAI-compatible LLM gateway (`titlegen.py`). Existing successful cache entries are preserved (no mass regeneration).

**Title-quality slice delivered (2026-09-12):**

1. Temporary titles prefer the scanner fallback (already the first real request after scanner scoring), then the raw first user message, then native title, over later confirmations, wrap-up commands and insults. Shortest-candidate ranking is gone; emotional prefixes are stripped when later text still names the task; Corral handoff wrappers (`Task: …` plus pickup boilerplate) are not titles.
2. Generation input is bounded task context (`user_request`, optional `later_user`, `assistant`, `native_title` as auxiliary, `inherited_task` as untrusted). The prompt must keep `PROMPT_MARKER`, must not call native titles the user's intent, and must allow `__INSUFFICIENT__` instead of inventing a title.
3. `__INSUFFICIENT__` is stored as `generation_state=insufficient` and retries only when the content fingerprint changes. Missing gateway configuration is `failure_reason=missing_config` and retries as soon as a virtual key is present; transport failures keep the six-hour cooldown.
4. Do not restore assistant CLI generation or read every transcript database on the list's first-paint path.

Still out of this host slice: iOS identity-store merge / stale-revision rejection on the phone (additive `revision` is already on the wire), end-to-end iPhone vs TUI screen acceptance, and provisioning a Corral virtual key on a machine that has none. Parent release verifies and ships; without a key the improved local fallback is what the list shows during cooldown.

Root cause was not fallback ranking but a starved pipeline — no gateway virtual key on this Mac (512 `missing_config` failures), so no model title had ever been produced there. Repaired without a pipeline refactor: created LiteLLM team `corral` with key `corral-mac2` (`$20/30d`, same budget as the canary teams), wrote `~/.config/corral/llm-gateway.json` (mode 600) with a temporary `model: openrouter-chat` override, and scrubbed the 30 `claude:sN` test-pollution entries from the real cache (backup in `/tmp`). Three gateway-transport bugs surfaced once calls flowed and were fixed in source with regression tests: `_assistant_text` only accepted string `content` (list-content answers became `transport` failures); `max_tokens` 256→2048, because routed reasoning models otherwise burn the budget and return `finish=length` with null content (~$0.0006/call); `_BATCH_SIZE` 5→1 and `_MAX_PARALLEL_BATCHES` 5→2, since large batches overflow the thinking budget and 5-way parallelism hangs while 2-way completes in ~3 s, plus per-chunk best-effort reuse of the least-recently-failed candidate so one unlucky probe no longer poisons a run (the pinned single-probe-then-stand-down behavior for a deterministically dead preferred generator is kept). `TITLE_CACHE_VERSION` 4→7 requeued the wrongful failure marks; accepted successes were never regenerated. ## Findings and evidence

- iOS `SessionPresentation.displayTitle` displays the received `SessionSummary.title`, falling back to the key when empty; both list rows and detail headers use this path and it does not generate an AI title.

## Local title-quality investigation (2026-09-12)

Diagnosis recorded and the title-quality slice implemented the same day. The installed Mac command then reported 0.24.191 and loaded this checkout through its pipx interpreter. A read-only `corral list --limit 300 --compact` returned 730 sessions: Cursor 277, Codex 236, OpenCode 189, Pi 20, Claude 8, no Kimi. Six deterministic samples per represented runtime plus targeted anomalies were inspected, comparing displayed titles, cache state, scanner excerpts and native history metadata. Counts describe this bounded scan, not all history or a measured bad-title rate; historical cache entries retain no generator/model/request provenance.

### Confirmed failure paths

| Symptom | Evidence and mechanism |
|---|---|
| An insult replaces a meaningful task title | A Cursor sample had a meaningful native title and an initial question about assembling annotation requests, but its final user prompt started with an insult followed by the real request; `_compact_title` split at punctuation, kept the insult, and `_temporary_title` chose it for being shorter than every meaningful candidate. An independent Codex sample and OpenCode samples show the same shortest-candidate problem |
| `Session recap` replaces the original task | Four Cursor rows showed this title. Their final prompt was `/doc-update`; `_normalize_title` translated that command through `session.title.cmd.doc_update` and the label won the shortest-candidate comparison. This is Corral's command label, not a model hallucinating a summary; English labels can appear on Chinese conversations via this fallback |
| `Task` after switching assistants | Two Codex samples and one Claude sample began with Corral's handoff text `Task: ...`; `_compact_title` split at the colon, kept `Task` (four characters) and accepted it as meaningful. One chain starts at the Cursor `实现` sample and carries that weak title into the Claude handoff — a shared handoff/presentation defect, not proof that either parser misidentified the runtime |
| `实现`, `执行` and similar context-free replies | The Cursor `实现` sample had a native title describing a CI problem, but its first prompt was only `实现`, so shorter text displaced the useful native title. Two OpenCode `执行` samples had clear initial tasks (application code, restoring an installed utility) yet the final confirmation won. Excluding a few known small-talk strings is insufficient |
| Old `空白会话` / `新建会话` remains on a substantive conversation | Two Codex records were accepted as successful cached titles although current excerpts clearly described icon variants and fixing application exit; the validator rejects some synonymous empty-session phrases but accepts these, and accepted successes ignore later content growth. The original generation input, model and failure timeline are not retained, so the historical origin is unproven. A separate `回复正常` sample really was a response-check task, so short titles alone are not evidence of corruption |
| No automatic recovery from weak fallback titles | The installed interpreter reported no configured gateway key, no default config file and zero available generators. In the 730-row scan, 266 rows had failed cache records, 432 non-failed, 32 no matching record; the complete cache snapshot held 857 entries including 287 failures, plus entries outside the scan and test-looking identities, so its total is not the number of real sessions. Missing configuration enters `_persist_failed_sessions` without a model request, and failed records impose a six-hour cooldown, so retrying cannot help while configuration is absent. This verifies the invoking environment, not the unseen environment of every running process |

Failed-cache titles are not necessarily what the user sees: `resolve_initial_title` recomputes the local fallback during cooldown. In the insult sample the persisted failed title was still meaningful while the displayed title had already degraded to the latest insult, so inspecting `titles.json` alone would miss it.

### Runtime-specific input limitations

- Cursor supplies its native metadata title as first fallback candidate, with first/last prompts from `prompt_history.json` (newest first), and leaves the assistant excerpt empty in the list path. Before 2026-09-12 the batch prompt called `preferred_title` the "best user intent"; current prompts label `native_title` as auxiliary metadata. The `实现` sample has little task information in its three plain prompt-history entries, though its native title supplies useful context.
- Codex and Claude can receive Corral handoff wrappers as their first apparent user request; the wrapper must not become the task, and a short excerpt can be consumed by boilerplate before reaching inherited context.
- OpenCode provided useful initial task and assistant excerpts in the inspected examples, so their loss occurred in shared fallback selection — a blanket OpenCode parser rewrite is not supported.
- All 20 returned Pi rows had non-failed cache entries and six sampled titles were interpretable; this neither establishes universal Pi correctness nor supports blaming Pi for the reported symptoms.

### Remediation boundaries and acceptance

At investigation time, generation readiness meant a temporary candidate passed a small lexical rejection list, not that the task was understandable — `Task` and `实现` passed. A result then became stable without a recorded input-quality assessment. The prompt used only `preferred_title`, first user, last user and last assistant excerpts, each capped at 300 characters; intermediate planning context was absent and raw handoff text could consume the user excerpt. Repair must separate "not enough task information yet" from a transport failure or a valid final title: a later substantive request should allow a previously insufficient candidate to be reconsidered, while a trailing confirmation, command or emotional remark should not replace an established task. This does not require regenerating after every message or waiting for the session to end.

Delivered behavior matching those boundaries:

1. Restore the configured shared-gateway route and expose distinct failure causes (missing configuration vs transport/invalid); missing-config failures retry when a virtual key appears. Do not restore assistant CLI generation.
2. Rank candidates by task information and source, not minimum length: preserve useful intent after emotional prefixes, treat closing commands and context-dependent confirmations as secondary, strip handoff framing before compacting. Do not solve this by filtering only the four reported strings.
3. Give bounded title input explicit provenance and meaningful task context from fields already on the session; when first/last excerpts are insufficient the model may return `__INSUFFICIENT__`, and do not read all transcript databases on first paint.
4. Repair only demonstrably invalid accepted cache records (wrapper fragments, empty-session placeholders, bare command labels, context-free action words) and keep valid stable titles; merely raising `TITLE_CACHE_VERSION` does not invalidate accepted successes.
5. Recheck targeted real sessions after install: insult suffix, `/doc-update` suffix, `Task:` handoff, `实现`/`执行`, cached `空白会话`/`Session recap`, and missing gateway key — confirming actual displayed task meaning through the installed command.

## Proposed ownership

Keep this feature in the Corral host domain. SessKit remains responsible for parsing native histories and supplying title candidates, not Corral model credentials, scheduling or presentation policy; the relay transports ciphertext only.

1. **Shared title repository:** host-side `TitleState` used by TUI and remote, owning resolved text via the durable title file, generation state and revision. Keep existing successful titles; do not invalidate them because the backend changes.
2. **One generation worker per host/user:** both TUI and remote signal missing work through the same spawn launcher, retaining detached execution, process-level exclusion, batch limits, failure cooldown and no-task-information filtering. Recheck persisted success under the lock before requesting a model; provider routing and fallback remain gateway responsibilities.
3. **Independent title updates:** completion notifies remote subscribers without waiting for history mtime, using additive monotonic `revision` on list snapshots and metadata events while retaining the string `title` for old clients.
4. **One iOS session record per host and canonical session:** phone-side follow-on — merge list/search/detail through one identity store and reject stale revisions.
5. **Offline and recovery:** display the last successfully synchronized title immediately while offline; never regenerate on the phone.

A successful title stays stable as conversation content grows. Re-generation of existing **valid** successes is outside this proposal; demonstrably invalid cached strings may be replaced. Preserve the language rule: infer title language from user conversation content, never from phone UI language.
